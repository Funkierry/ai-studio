# AI 工作室

一个本地工具：写下要做什么，几位 AI 员工分工把它做出来，你在同一页看到过程和成品，成品同时保存到本机文件夹。你是老板：提要求、拍板、验收。
公司需要记录的东西都是真的：Git 代码库、文档库、数据库和各类事务记录。

## 运行

需要 Node.js 22.13 以上（自带 SQLite）和 Git。

```bash
npm install
node server.js
```

打开 http://localhost:5300 就是工作台。用法只有三步，都在这一页：

1. **你的要求**。在「要做什么？」里写清楚目标，选要什么成品（一份文档、一个小程序、一个完整项目），按「开始」。
2. **过程**。谁做哪一份、做到哪了，一眼看得到；下面按时间列出每个人说了什么、交了什么、你做过什么决定。每条记录都能点开，看当时交给模型的任务书和模型的回复。
3. **成品**。做出来的文件列在右边，可以直接预览；同时已经保存在本机的文件夹里，点「打开文件夹」就到。

左边是所有工作：等你处理的排最上面，然后是进行中的，已完成的收在最下面。顶部可以切到「办公室」看现场画面（也可以按 1 / 2，按 N 新建工作）；http://localhost:5300/company.html 是文件与记录。

需要你出手的事都集中在左上角的「等你处理」：待验收、待确认、员工的提问、失败或被卡住的工作。点开后页面顶部会说明在等你做什么，按钮就在旁边。浏览器标签页标题也会显示待处理数量。

### 成品保存在哪

每项工作在成品文件夹里有一个自己的文件夹，员工每交付一次就更新一次，不用等验收：

```
成品/
  3-番茄钟/
    程序/          可以直接运行的代码（web/、server/、tests/、README.md……）
    文档/          工作单、每份分工的交付文档、项目总结
    过程记录.md    按时间记下每个人说了什么、交了什么、你的每个决定
    过程记录/      每次模型调用一个文件：完整的任务书和回复
  周报-1a2b3c4d/
    周报.md
    过程记录.md
```

- 默认位置是项目目录下的 `成品/`，启动时会打印出来；用 `--out <目录>` 或环境变量 `STUDIO_OUT` 可以换地方。
- 页面上显示每项工作的完整路径，可以「打开文件夹」或「复制路径」；顶部的「成品文件夹」打开总目录。
- 验收前，文件夹里是「进行中的当前版本」；验收通过后换成正式版。之后这些文件就归你了：你在文件夹里改的、加的东西不会被覆盖或删除，后续只更新过程记录。
- 以前做完的工作，启动时会一次补齐。

### 办公室里能看到什么

顶部切到「办公室」，是同一批工作的现场画面，旁边是员工名单（添加员工、改设置都在这里）。点一位员工会回到 TA 手上的那项工作。

- **每个人一种颜色**。名牌、工位上的小旗、走路的路线和脚印、工作台里的分工卡片都用这一种颜色，办公室下方的一排名签写着每个人此刻在做什么，点一下会在画面里把 TA 圈出来。
- **路线看得见**。员工走动时，前方是一条本人颜色的虚线，终点有一个标记；身后留下几步脚印。每个人在走廊里走自己的一条道，两个人同路也不会叠在一起。
- **每个岗位有自己的去处**。执行任务时员工不只是坐着：产品经理去会议室的白板，前端去墙上的预览屏，后端去机柜，测试去测试台，设计去画板，调研去资料架，文案去阅览桌。到了以后停一会儿再回工位。这只表示「谁是做什么的」，不代表模型当时在执行什么。
- **工位会说话**。有人在写的时候屏幕亮着，内容随岗位不同（代码、页面、清单、勾选、图表）。
- **墙上是真实数据**。茶水间上方的交付墙每行是一项进行中的工作，每格是一份分工的状态；会议室白板上每张便签是一项工作；老板桌上的文件堆是「等你处理」的数量；墙上的钟是现在的时间，窗外的天色、傍晚和夜里的灯光也跟着真实时间变。
- **点房间**可以打开真实系统：机房是代码库，档案室是文档库，老板办公室是事务记录。

办公室里的小人可以长按拿起，用鼠标时按住直接拖也行。放到空闲的同事身上会击掌，放到忙碌的同事身上会打气，放进茶水间会去接咖啡，放到其他房间也各有反应；用力晃会头晕。正在忙的人放下后会自己走回去，任务不受影响。

平时员工会自己互动：凑在一起聊天、给正在工作的同事送咖啡、站到同事身后看看进度、浇花、翻资料，在走廊里碰见会打招呼。真实协作也会表现出来：

- 项目讨论时全组到会议室，发言人的真实回复显示成气泡，同时一封信飞向这句话的对象（某位同事、全组或你的座位）。
- 上一棒做完，交付飞到下一位手里，本人也会走过去说一声。
- 被打回返工时，一份红色的修改单从提出的人那里飞来：你打回的从你的座位出发，同事提出的从同事那里出发。
- 你留言、确认、验收、打回，都会从你的座位飞出一封信、一个通过章或一份修改单，落到那位员工头上。
- 任务失败时有同事过来安慰；验收通过时一起庆祝。

这些都只是画面，不调用模型，也不产生费用。

界面按「先回应、不打断」来做：按下按钮立刻有反馈，操作完马上刷新；数据更新时只改变化的部分，不会吞掉正在按的按钮，也不会动输入框和滚动位置。系统开启减少动态效果时，页面切换和折叠的过渡都会关掉。页面不在前台时暂停刷新，切回来马上补上。

「一个完整项目」默认开启员工自主协作：填写目标即可开始。员工先讨论形成共同约定，前后端再并行开工，测试员工读取双方实际代码进行验证。测试失败时，测试员工根据失败报告点名责任分工，系统自动重跑这些分工和下游测试；通过最终集成检查后发布本地成果。小任务可以选「一个小程序」或「一份文档」，也可以在「更多设置」里关闭自主协作，保留人工确认和验收。

### 看员工交流、给项目留言

选中一个项目，「过程」里的记录保留每位员工的实际模型发言、接收人、交付、测试结果和返工要求。员工提出问题时会单独调用接收员工回复，其他员工的后续任务也会读取这些消息。系统调度记录与员工发言分别标记，旧项目不会补造历史对话。记录可以按「对话 / 交付 / 我的决定」筛选，点流程里的一份分工可以只看这一份。

记录下方的输入框可以补充要求、回答关键问题，并选择接收员工。消息持久化保存，重复发送同一请求不会重复调用；刷新或关闭浏览器不影响执行。正在运行的调用先完成，再处理新消息。办公室里的员工忙碌状态也包括实际讨论调用。

自动返工最多 2 轮，自动讨论最多 20 次调用；关键需求不清、模型调用失败、服务重启导致中断、达到上限或最终集成失败时会停止并显示原因。讨论中断需明确点击重试，不会自动重复计费。暂停会保留已发出的调用结果并阻止后续调用。已发布项目可以继续解释成果，新的代码修改需要新建后续任务。自动验收只发布本机项目仓库，不进行云部署或向 GitHub 发布用户项目。

所有讨论与实际行动在 `project_messages`、`discussion_turns`、`project_team` 表中持久化；每次模型调用的任务书、回复、用时和费用在 `calls` 表里，页面上的「看任务书和回复」读的就是它。代码生成仍由当前四种分工模板执行，员工可以协商具体实现约定，尚不支持自行增加岗位或重建依赖图。

可选参数：`--port 5300`、`--data <目录>`（默认是项目里的 `data/`）、`--out <目录>`（成品保存到哪，默认是项目里的 `成品/`）、`--fake-llm`（用测试替身代替真实模型，不花钱，只用来测流程）。

## 接入 AI：本机和 API

「添加员工」先选「本机」或「API 接入」，再选工具 / 模型。员工列表显示当前接入方式，已有员工可点「设置」修改。选择保存到每位员工，项目讨论与交付都遵循该选择；选择失败时不会自动切换到另一种接入。员工调用进行中时需等调用完成后修改。

旧员工未保存过选择时保留原来的自动检测规则，保存接入设置后固定为所选方式。下面说明两种方式及自定义模型的配置。

### 1. 本机已经装好的 AI 工具（不需要 API 密钥）

如果电脑上装了并登录了这些命令行工具，员工会直接调用它们，用的是你自己账号的额度：

| 工具 | 谁会用它 | 说明 |
|---|---|---|
| Claude Code（`claude`） | 选择「本机」的 Claude 员工 | `STUDIO_CLAUDE_CLI_MODEL` 可以指定模型，不设就用你在 Claude Code 里的默认模型 |
| Codex（`codex`） | 选择「本机」的 Codex / GPT 员工 | `STUDIO_CODEX_MODEL` 可以指定模型 |

调用时会给它们一个空的临时文件夹，并且只给只读权限：它们只负责把文字和代码写回来，不会改你电脑上的文件。

「本机」指从本机工具发起调用，仍使用该工具的登录及计费配置，通常会访问云端模型，不代表离线推理。

### 2. 各家的 API 密钥

把密钥写进 `.env`（照 `.env.example`）或者系统环境变量：

| 员工 | 变量 | 默认模型 |
|---|---|---|
| 克劳德这一类 | `ANTHROPIC_API_KEY`（或先运行 `ant auth login`） | `claude-opus-5-5`，`STUDIO_CLAUDE_MODEL` 可改 |
| 阿 G、小码这两类 | `OPENAI_API_KEY` | `gpt-5`，`STUDIO_OPENAI_MODEL` 可改；`STUDIO_OPENAI_PRICE=输入,输出`（美元/百万 token）用于记账 |
| DeepSeek 员工 | `DEEPSEEK_API_KEY` | `deepseek-flash`，`STUDIO_DEEPSEEK_MODEL=deepseek-v4-pro` 可换大模型 |

选择「API 接入」后仅使用对应 API。未配置的选项会显示缺少的配置，填写 `.env` 后重启工作室。界面不会读取或展示密钥内容。

### 3. 任何兼容 OpenAI 接口的模型（新增一种员工）

通义千问、Kimi、智谱、本地的 Ollama 等，只要接口兼容 OpenAI，就能变成一种新员工，不用改代码：

1. 把 `models.example.json` 复制成 `models.json`，按里面的格式填：`type`（英文代号）、`label`（显示名）、`baseURL`、`keyEnv`（存密钥的环境变量名）、`model`，可选价格、默认名字、特点。
2. 把密钥写进 `.env` 或系统环境变量（变量名就是你填的 `keyEnv`）。本地模型不需要密钥，写 `"noKey": true`。
3. 重启服务器，招聘窗口里就会出现这种员工。

地址为 localhost、127.0.0.1 或 ::1 的自定义服务归入「本机」，其他自定义服务归入「API 接入」。

## 创建员工

右侧「员工」面板点「＋ 添加」，选好工具 / 模型就能加，名字会自动填好。点员工可以看 TA 手上的工作，点「设置」可以随时改名字、岗位、专长和接入方式。同一种模型可以有多位员工，并分别选择本机或 API 接入（以该模型支持的方式为准）。
员工只在真实调用期间显示忙碌；等待你验收不会占住员工。同一员工的多项任务按队列执行。
未配置的模型无法添加，需要先按上面的步骤接入。模型通过 CLI 调用时，无法获取的费用不会估算为真实账单。

## 安排工作

在「要做什么？」里写清楚目标和怎样算完成，选要什么成品，按「开始」（Ctrl+Enter 也可以）。下面一句话写着这次谁来做；点「换人」会展开分工流程，每一步都可以当场换人。默认按岗位安排，文档优先交给文案岗位。标题和协作方式收在「更多设置」里。写到一半去看别的工作再回来，内容还在。没有员工时会先带你添加一位。

- **一份文档**：撰写 → 你验收。
- **一个小程序**：开发 → 测试 → 你验收。开发交付自动传给测试负责人，测试会实际运行。
- **一个完整项目**：员工讨论 → 需求规划 → 前后端并行开发 → 集成测试 → 验收。自主模式会处理测试返工，并在通过检查后自动验收。

### 过程：分工、记录、留痕

「过程」最上面从左到右画出流程：每份分工一张卡片（负责人的头像和颜色、状态、用时），同一列的同时进行，最后一格是你的验收。点一张卡片展开这份分工：状态、测试结果、失败原因，以及「修改 / 重试」的入口；同时下面的记录只显示这一份。点负责人可以到办公室找到 TA。

记录按时间排列，每条写明谁对谁、是什么（要求、讨论、提问、交付、执行结果、要求修改、确认、验收发布）。带模型调用的记录下面写着模型、用时和费用，点「看任务书和回复」打开一个窗口：左边是当时交给模型的完整任务书，右边是模型的回复。正在执行的调用显示在记录下方，任务书此时就能看。交付记录上的文件标签点一下，右边就打开那个文件。

### 成品与验收

「成品」里是这项工作做出来的文件，分成程序、文档和过程记录。点文件直接看：文档按排版显示，代码显示原文，网页可以直接预览（要用到后端的功能，需按 README 启动程序）。

轮到你验收时，「成品」最上面出现验收面板：

- 清单：几份分工完成、自动化测试通过和失败的数量、有没有生成失败或冲突的交付。
- 一个决定：评 1 到 3 星后「验收通过」（会再跑一次集成检查，通过后合并代码、打版本标签、写项目总结，并把正式版保存到成品文件夹），或者「打回修改」，选让谁改、写清哪里不对，那份分工和依赖它的后续步骤会重做。

单份文档同样是看成品、通过或打回。需要你中途确认的分工（非自主模式的需求规划）会在流程里标成「待确认」，并出现在「等你处理」。

「修改 / 重试」接受具体反馈，并重新执行依赖它的后续步骤。项目有调用进行中时需等待本次调用结束，避免用旧结果覆盖修改。分支保留历史，只有整体验收且集成测试通过后才合并到 main、创建版本标签。

### 执行与恢复

- 服务端保存和调度任务，刷新、关闭浏览器或多开页面不会重新发出模型调用。
- 每位员工同时执行一项任务，全局最多三个调用。待验收的员工可以接其他任务。
- 「暂停后续步骤」会保留已经发出的调用及结果；点击「继续执行」恢复队列。
- 服务重启时，未完成的调用标为「调用中断」，检查结果后填写重试要求；不会自动重复扣费。
- 升级前的项目保留，可以手动启动接管。旧演示订单保留在记录中，但隐藏于工作区并停止自动执行。
- 费用只展示记录到的模型调用成本，不再累计办公室动画产生的模拟费用。

### 员工拿到的材料

模型会收到目标、分工、岗位与专长、上游交付、当前代码和具体修改意见。返工时读取新上游代码。每次实际发出的任务书都能在页面上点开，也保存在成品文件夹的「过程记录」里和 `data/briefs/`。
纯前端任务不强制引入后端；测试应检查实际实现，模型失败、测试失败、没有测试或全跳过都不能作为已完成的代码项目发布。

### 查询 AI 协作聊天记录

要跨项目搜索员工之间的对话，打开 `/company.html#chat`。可按项目、参与员工、正文关键词、消息类型和时间组合筛选；结果区分真实模型产出、人工消息、系统记录、测试替身及未标记来源。点击消息可查看原始提问、回复链和同项目相邻消息。导出会包含全部匹配记录，不限于当前页。

其他 AI 或脚本可以使用只读工具，返回结构化 JSON，不触发模型调用：

```sh
node scripts/query-chat.js --project 1 --q 验收口令 --all
node scripts/query-chat.js --context 4
node scripts/query-chat.js --url http://localhost:5301 --project 1 --all --out E:/CodexWorkspace/Outputs/chat-history.json
```

HTTP 接口：`GET /api/collaboration/messages`（参数 `project`、`participant`、`sender`、`q`、`kind`、`since`、`until`、`limit`、`before`、`snapshot`）；`GET /api/collaboration/messages/:id/context`；`GET /api/collaboration/filters`。日期使用带时区的 ISO 时间。分页上限 200 条，用响应的 `nextBefore` 和 `snapshot` 继续查询，避免新消息造成重复或遗漏。关键词按字面匹配，百分号和下划线不作为通配符。参与员工筛选匹配直接发送者或接收者，不推断群发消息的已读成员。

2026-10-31 实测：Claude Code 与 DeepSeek API 在非模拟模式下完成 3 次讨论和 2 次文档交付。Claude 先提问，DeepSeek 自行生成英文验收口令；Claude 文档原样引用该口令，DeepSeek 读取上游文档后逐字核对。8 条消息、回复关联和两份交付均已持久化。此实测验证了跨模型讨论与文档交接；代码失败自动返工另由隔离回归测试覆盖，不等同于已经验证任意真实代码任务的质量。旧项目没有保存的聊天不会被补造。

| 系统 | 存在哪 | 内容 |
|---|---|---|
| 代码库 | `data/repos/` | 每个项目、每个代码类订单一个 Git 仓库；项目里每个开发分工一个分支和合并请求，测试在包含上游代码的独立分支真实运行，验收时集成验证后合并并打版本标签 |
| 文档库 | `data/docs/`，一个 Git 仓库 | 工作单、各分工的交付文档、订单交付物、会议纪要、项目总结；网页上可编辑，每次保存都是一个新版本 |
| 业务数据库 | `data/biz/<项目>.db` | 后端分工建的数据表和示例数据 |
| 事务记录 | `data/company.db` | 任务工单、项目与分工、审批与决策、交付验收、打回记录、会议、合并请求、花费账本、每次模型调用的任务书和回复、员工档案、动态日志 |
| 成品 | `成品/<工作>/` | 给人直接用的普通文件：程序、文档、过程记录。由上面几个系统导出，不是另一份数据 |

所有这些都可以直接用普通工具打开：`git log`、任何 SQLite 客户端、任何 Markdown 编辑器。

## 还是模板或模拟的部分

- 像素办公室只展示员工执行状态，不参与派单或计费；员工去岗位站点、互相聊天等动作是画面效果，不对应模型的具体操作。
- 小人会走回工位打字、把文件交给下游员工、送交付到老板门口，并在空闲时逛茶水间。这些动画由真实任务状态驱动，轮询不会把人物搬回固定位置。
- `--fake-llm` 明确使用测试替身，只用于流程验证，不能代替真实交付。
- Gemini 员工还没接入（可以用 `models.json` 按兼容接口接入）。

## 目录

- `server.js`：本地服务和接口
- `lib/execution.js`：服务端任务队列、依赖、暂停、重试和状态恢复
- `lib/trail.js`：一项工作的过程记录（要求、发言、交付、决定和每次模型调用），页面和导出的过程记录都从这里来
- `lib/outputs.js`：把成品保存成本机文件夹里的普通文件
- `lib/preview.js`：独立来源的静态交付预览
- `lib/company.js`：公司系统的业务逻辑（订单、立项、分工交付、合并、验收、记录）
- `lib/writer.js`：让员工的模型写交付物（提示词约定、输出结构、校验、选择用哪个模型、退回模板）
- `lib/providers/`：Claude（Anthropic SDK）、GPT（OpenAI SDK）、兼容 OpenAI 的接口（DeepSeek 和 `models.json` 里的）、本机的 Claude Code 和 Codex
- `lib/produce.js`：交付文档的排版，以及模型不可用时的模板
- `lib/git.js`、`lib/store.js`：Git 和数据库
- `public/index.html`、`public/app.js`：页面入口；连不上本地服务时只显示启动方法（页面本身不带演示数据）
- `public/office/`：像素办公室。`world.js` 平面图、站位和路线；`roster.js` 员工外观、岗位和每人的颜色；`sprites.js` 小人和头像；`backdrop.js` 背景、墙上的实时内容和昼夜灯光；`motion.js` 把真实任务状态变成走动和信件；`social.js` 员工之间的互动；`routines.js` 岗位专属路线；`stage.js` 画面、拖动和特效
- `public/workspace.js`、`public/workspace.css`：工作台；`public/ui/` 是它的各个部分：`model.js` 从服务端数据算出待办、分工流程、验收清单、记录筛选和文件分组，`views.js` 生成页面各部分，`compose.js` 是新工作的输入框，`dialogs.js` 是「任务书和回复」窗口和员工设置窗口，`markdown.js` 把交付文档显示成排版好的页面
- `public/dom-patch.js`、`public/live-refresh.js`：面板就地更新和刷新调度
- `public/theme.css`：配色和办公室样式；`public/company.html`：文件与记录
- `tests/`：隔离的 Git、SQLite 和执行流程回归测试，运行 `npm test`
