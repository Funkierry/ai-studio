# AI 工作室

多个 AI 员工在一间像素办公室里协作干活的本地系统。你是老板：发订单、安排分工、拍板、验收。
公司需要记录的东西都是真的：Git 代码库、文档库、数据库和各类事务记录。

## 运行

需要 Node.js 22.13 以上（自带 SQLite）和 Git。

```bash
npm install
node server.js
```

打开 http://localhost:5300 默认进入像素工作室，顶部可切换「任务工作台」查看详细交付；http://localhost:5300/company.html 是文件与记录。

「新工作」默认开启员工自主协作：填写目标即可开始，标题和团队成员可调整。员工先在「项目讨论」里形成共同约定，前后端再并行开工，测试员工读取双方实际代码进行验证。测试失败时，测试员工根据失败报告点名责任分工，系统自动重跑这些分工和下游测试；通过最终集成检查后发布本地成果。小任务仍可选择「小型代码」或「文档」流程，也可以关闭自主协作，保留人工确认和验收。

### 看员工交流、给项目插话

顶部点击「项目讨论」，或在任务详情点「查看项目讨论」。群聊保留每位员工的实际模型发言、接收人、回复关系、交付链接、测试结果和返工记录。员工提出问题时会单独调用接收员工回复，其他员工的后续任务也会读取这些消息。系统调度记录与员工发言分别标记，旧项目不会补造历史对话。

下方输入框可以补充要求、回答关键问题，并选择接收员工。消息持久化保存，重复发送同一请求不会重复调用；刷新或关闭浏览器不影响执行。正在运行的调用先完成，再处理新消息。「像素工作室」里的员工忙碌状态也包括实际讨论调用。

自动返工最多 2 轮，自动讨论最多 20 次调用；关键需求不清、模型调用失败、服务重启导致中断、达到上限或最终集成失败时会停止并显示原因。讨论中断需明确点击重试，不会自动重复计费。暂停会保留已发出的调用结果并阻止后续调用。已发布项目可以继续解释成果，新的代码修改需要新建后续任务。自动验收只发布本机项目仓库，不进行云部署或向 GitHub 发布用户项目。

所有讨论与实际行动在 `project_messages`、`discussion_turns`、`project_team` 表中持久化；实际提示词保存在 `data/briefs/<项目>/讨论-*.md`。代码生成仍由当前四种分工模板执行，员工可以协商具体实现约定，尚不支持自行增加岗位或重建依赖图。

可选参数：`--port 5300`、`--data <目录>`（默认是项目里的 `data/`）、`--fake-llm`（用测试替身代替真实模型，不花钱，只用来测流程）。

## 接入 AI：本机和 API

「添加员工」先选「本机」或「API 接入」，再选工具 / 模型。员工列表显示当前接入方式，已有员工可点「接入设置」修改。选择保存到每位员工，项目讨论与交付都遵循该选择；选择失败时不会自动切换到另一种接入。员工调用进行中时需等调用完成后修改。

旧员工未保存过选择时保留原来的自动检测规则，保存接入设置后固定为所选方式。下面说明两种方式及自定义模型的配置。

### 1. 本机已经装好的 AI 工具（不需要 API 密钥）

如果电脑上装了并登录了这些命令行工具，员工会直接调用它们，用的是你自己账号的额度：

| 工具 | 谁会用它 | 说明 |
|---|---|---|
| Claude Code（`claude`） | 选择「本机」的 Claude 员工 | `STUDIO_CLAUDE_CLI_MODEL` 可以指定模型，不设就用你在 Claude Code 里的默认模型 |
| Codex（`codex`） | 选择「本机」的 Codex / GPT 员工 | `STUDIO_CODEX_MODEL` 可以指定模型 |

调用时会给它们一个空的临时文件夹，并且只给只读权限：它们只负责把文字和代码写回来，不会改你电脑上的文件。

「本机」指从本机工具发起调用，仍使用该工具的登录及计费配置，通常会访问云端模型，不代表离线推理。

### 2. 各家的 API 密钥

把密钥写进 `.env`（照 `.env.example`）或者系统环境变量：

| 员工 | 变量 | 默认模型 |
|---|---|---|
| 克劳德这一类 | `ANTHROPIC_API_KEY`（或先运行 `ant auth login`） | `claude-opus-5-5`，`STUDIO_CLAUDE_MODEL` 可改 |
| 阿 G、小码这两类 | `OPENAI_API_KEY` | `gpt-5`，`STUDIO_OPENAI_MODEL` 可改；`STUDIO_OPENAI_PRICE=输入,输出`（美元/百万 token）用于记账 |
| DeepSeek 员工 | `DEEPSEEK_API_KEY` | `deepseek-flash`，`STUDIO_DEEPSEEK_MODEL=deepseek-v4-pro` 可换大模型 |

选择「API 接入」后仅使用对应 API。未配置的选项会显示缺少的配置，填写 `.env` 后重启工作室。界面不会读取或展示密钥内容。

### 3. 任何兼容 OpenAI 接口的模型（新增一种员工）

通义千问、Kimi、智谱、本地的 Ollama 等，只要接口兼容 OpenAI，就能变成一种新员工，不用改代码：

1. 把 `models.example.json` 复制成 `models.json`，按里面的格式填：`type`（英文代号）、`label`（显示名）、`baseURL`、`keyEnv`（存密钥的环境变量名）、`model`，可选价格、默认名字、特点。
2. 把密钥写进 `.env` 或系统环境变量（变量名就是你填的 `keyEnv`）。本地模型不需要密钥，写 `"noKey": true`。
3. 重启服务器，招聘窗口里就会出现这种员工。

地址为 localhost、127.0.0.1 或 ::1 的自定义服务归入「本机」，其他自定义服务归入「API 接入」。

## 创建员工

工作区顶部点「添加员工」，填写名字，选择接入方式、工具 / 模型、岗位和专长。同一种模型可以有多位员工，并分别选择本机或 API 接入（以该模型支持的方式为准）。
员工只在真实调用期间显示忙碌；等待你验收不会占住员工。同一员工的多项任务按队列执行。
未配置的模型无法添加，需要先按上面的步骤接入。模型通过 CLI 调用时，无法获取的费用不会估算为真实账单。

## 安排工作

顶部「＋ 新工作」填写目标和验收标准，标题可选；默认使用自主团队协作，也可展开选项调整交付方式及负责人：

- **团队协作**：员工讨论 → 需求规划 → 前后端并行开发 → 集成测试 → 整体验收。自主模式会处理测试返工并在通过检查后自动验收。
- **小型代码**：开发 → 测试 → 整体验收。开发交付自动传给测试负责人，可以由同一员工先后完成。测试会实际运行。
- **文档**：撰写 → 验收。完成后可打开交付文档，确认通过或填写具体修改意见。

工作列表显示当前状态，点开后可看每份分工、负责人、开始与结束时间、实际测试结果和失败原因。交付旁可直接打开文档、代码文件、提交差异和静态 HTML 预览；需要后端的项目按 README 启动服务。

「修改 / 重试这份分工」接受具体反馈，并重新执行依赖它的后续步骤。项目有调用进行中时需等待本次调用结束，避免用旧结果覆盖修改。分支保留历史，只有整体验收且集成测试通过后才合并到 main、创建版本标签。

### 执行与恢复

- 服务端保存和调度任务，刷新、关闭浏览器或多开页面不会重新发出模型调用。
- 每位员工同时执行一项任务，全局最多三个调用。待验收的员工可以接其他任务。
- 「暂停后续步骤」会保留已经发出的调用及结果；点击「继续执行」恢复队列。
- 服务重启时，未完成的调用标为「调用中断」，检查结果后填写重试要求；不会自动重复扣费。
- 升级前的项目保留，可以手动启动接管。旧演示订单保留在记录中，但隐藏于工作区并停止自动执行。
- 费用只展示记录到的模型调用成本，不再累计办公室动画产生的模拟费用。

### 员工拿到的材料

模型会收到目标、分工、岗位与专长、上游交付、当前代码和具体修改意见。返工时读取新上游代码，实际提示词保存在 `data/briefs/`。
纯前端任务不强制引入后端；测试应检查实际实现，模型失败、测试失败、没有测试或全跳过都不能作为已完成的代码项目发布。

## 公司系统里有什么

### 查询 AI 协作聊天记录

办公室顶部点「查询协作记录」，或打开 `/company.html#chat`。可按项目、参与员工、正文关键词、消息类型和时间组合筛选；结果区分真实模型产出、人工消息、系统记录、测试替身及未标记来源。点击消息可查看原始提问、回复链和同项目相邻消息。导出会包含全部匹配记录，不限于当前页。

其他 AI 或脚本可以使用只读工具，返回结构化 JSON，不触发模型调用：

```sh
node scripts/query-chat.js --project 1 --q 验收口令 --all
node scripts/query-chat.js --context 4
node scripts/query-chat.js --url http://localhost:5301 --project 1 --all --out E:/CodexWorkspace/Outputs/chat-history.json
```

HTTP 接口：`GET /api/collaboration/messages`（参数 `project`、`participant`、`sender`、`q`、`kind`、`since`、`until`、`limit`、`before`、`snapshot`）；`GET /api/collaboration/messages/:id/context`；`GET /api/collaboration/filters`。日期使用带时区的 ISO 时间。分页上限 200 条，用响应的 `nextBefore` 和 `snapshot` 继续查询，避免新消息造成重复或遗漏。关键词按字面匹配，百分号和下划线不作为通配符。参与员工筛选匹配直接发送者或接收者，不推断群发消息的已读成员。

2026-10-31 实测：Claude Code 与 DeepSeek API 在非模拟模式下完成 3 次讨论和 2 次文档交付。Claude 先提问，DeepSeek 自行生成英文验收口令；Claude 文档原样引用该口令，DeepSeek 读取上游文档后逐字核对。8 条消息、回复关联和两份交付均已持久化。此实测验证了跨模型讨论与文档交接；代码失败自动返工另由隔离回归测试覆盖，不等同于已经验证任意真实代码任务的质量。旧项目没有保存的聊天不会被补造。

| 系统 | 存在哪 | 内容 |
|---|---|---|
| 代码库 | `data/repos/` | 每个项目、每个代码类订单一个 Git 仓库；项目里每个开发分工一个分支和合并请求，测试在包含上游代码的独立分支真实运行，验收时集成验证后合并并打版本标签 |
| 文档库 | `data/docs/`，一个 Git 仓库 | 工作单、各分工的交付文档、订单交付物、会议纪要、项目总结；网页上可编辑，每次保存都是一个新版本 |
| 业务数据库 | `data/biz/<项目>.db` | 后端分工建的数据表和示例数据 |
| 事务记录 | `data/company.db` | 任务工单、项目与分工、审批与决策、交付验收、打回记录、会议、合并请求、花费账本、模型调用、员工档案、动态日志 |

所有这些都可以直接用普通工具打开：`git log`、任何 SQLite 客户端、任何 Markdown 编辑器。

## 还是模板或模拟的部分

- 工作区中的像素办公室只展示员工执行状态，不参与派单或计费。
- 小人会走回工位打字、把文件交给下游员工、送交付到老板门口，并在空闲时逛茶水间。这些动画由真实任务状态驱动，轮询不会把人物搬回固定位置。
- `--fake-llm` 明确使用测试替身，只用于流程验证，不能代替真实交付。
- Gemini 员工还没接入（可以用 `models.json` 按兼容接口接入）。

## 目录

- `server.js`：本地服务和接口
- `lib/execution.js`：服务端任务队列、依赖、暂停、重试和状态恢复
- `lib/preview.js`：独立来源的静态交付预览
- `lib/company.js`：公司系统的业务逻辑（订单、立项、分工交付、合并、验收、记录）
- `lib/writer.js`：让员工的模型写交付物（提示词约定、输出结构、校验、选择用哪个模型、退回模板）
- `lib/providers/`：Claude（Anthropic SDK）、GPT（OpenAI SDK）、兼容 OpenAI 的接口（DeepSeek 和 `models.json` 里的）、本机的 Claude Code 和 Codex
- `lib/produce.js`：交付文档的排版，以及模型不可用时的模板
- `lib/git.js`、`lib/store.js`：Git 和数据库
- `public/workspace.js`、`public/workspace.css`：真实工作区
- `public/index.html`：页面入口和办公室绘制；`public/company.html`：文件与记录
- `tests/`：隔离的 Git、SQLite 和执行流程回归测试，运行 `npm test`
